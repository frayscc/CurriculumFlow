# 多人账号、备课组与年度试卷资源库

多人功能运行在 Node / Docker 服务端；便携 HTML 仍为独立的个人离线版。

## 初次启用与旧数据

升级前停止容器并备份整个 `data` 目录，包含数据库和 WAL 文件。升级后先打开网页初始化首位管理员。初始化需要 `/data/setup-token` 中的密钥：

```bash
docker exec curriculumflow cat /data/setup-token
```

也可以在部署环境中设置自己的 `SETUP_TOKEN`。不要向其他人提供初始化密钥。首次初始化后，初始化接口自动关闭，没有公开注册入口。管理员密码至少 10 个字符。

旧 SQLite 工作空间原地保留，项目归首位管理员，按原学年、年级、学科自动创建备课组；原试卷、作者/审题人 ID 和附件不变。原来仅存在个人浏览器中的数据不会自动并入多人系统，可由管理员通过完整 ZIP 备份恢复。

## 管理流程

1. 管理员打开右上角“账号”，为学年、年级、学科创建备课组。
2. 创建教师账号，设置初始密码，选择组内老师或备课组长。一个账号可加入多个组，组长权限只适用于被授权的组。
3. 教师账号自动关联同名旧教师身份，也可明确选择已有命题/审题教师。一个教师身份最多绑定一个账号；同名教师需使用可区分的姓名。历史试卷姓名为快照，关联依靠稳定 ID。
4. 老师登录后修改自己的密码。管理员可重置密码或停用账号；权限调整和停用会立即撤销该账号已有会话。
5. 按对应备课组创建学期项目。备课组长在项目“试卷资源”页维护试卷与附件。

## 权限

| 操作 | 管理员 | 对应备课组长 | 普通老师 |
| --- | --- | --- | --- |
| 管理账号、备课组与成员 | 是 | 否 | 否 |
| 查看教学项目 | 全站 | 所在组 | 所在组 |
| 修改教学计划 | 全站 | 所在组 | 自己创建的项目 |
| 修改试卷与附件 | 全站 | 所在组 | 否 |
| 下载年度试卷资源 | 全站 | 全站 | 全站 |
| 恢复完整 ZIP 备份 / 修改共享命名模板 | 是 | 否 | 否 |

权限由服务端检查；修改页面或直接调用 API 不能跳过检查。不同组可以并行保存，服务端合并各自项目的变化。修改同一份记录时拒绝冲突写入并保留浏览器副本。每个账号使用独立 IndexedDB 缓存和同步基线，退出不会清除该账号尚未同步的修改。

组内只读老师可使用完整月历查看课程跨度、日期状态并切换月份，不能拖动、调整跨度、修改校历。服务端同时校验学期项目唯一性，防止两位老师同时创建重复项目。试卷、附件元数据、周备注等独立记录可合并；课程时间轴的自动顺延涉及多条关联记录，仍按项目保守拒绝并发修改，不能理解为实时协同编辑。

无变化时客户端只轮询版本号；服务器有变化时仍传输可见结构化快照，但本地仅更新变更记录。附件在下载、导出备份时读取并缓存，不因普通同步重复下载。离线修改基线保留，服务器用内容去重减少重复基线占用；当前未提供历史基线或孤立附件的自动空间清理，大规模长期部署需关注数据目录大小。

项目 ZIP 恢复会优先复用现有教师 ID、账号关联或同名已绑定教师，避免“我命题 / 审题”关联断开。未匹配到的教师作为未绑定身份恢复，不能凭备份伪造账号绑定。

## 整站备份与操作审计

管理员在“账号 → 系统备份与审计”可下载一致的 SQLite 数据库副本，包含账号、备课组、成员权限、所有项目、试卷、附件和审计记录；导出的副本清除登录会话，不影响正在使用的服务器会话。项目 ZIP 不包含整站账号权限，不能替代此备份。

恢复时停止容器，将备份重命名为 `curriculumflow.db` 放入一个新的空数据目录，修改数据卷映射，设置 UID/GID 1000 的读写权限后启动。原数据目录保留以便回退，不得把旧 WAL/SHM 文件与新备份混用。恢复后重新登录。

审计记录涵盖账号创建/修改、备课组创建、修改密码、工作空间提交和整站备份。页面展示最近 100 条，数据库保留全部记录；不记录密码明文、文件内容，不回填启用前的历史，不是逐字段版本回滚系统。备份与审计仅管理员可访问。

## 全校试卷库

右上角“试卷资源库”查询所有学年的试卷，可按学年、年级、学科、标题和命题/审题人筛选，也可查看“我命题 / 审题的试卷”。附件在点击下载时读取，可单文件下载或打包 ZIP；ZIP 中的文件在同一层目录。

年度归档来自项目学年。删除含试卷的教学项目时，服务端保留资源归档及附件，项目从教学工作空间隐藏，试卷仍可检索、下载，由对应组长继续维护。只有明确删除试卷或附件才移除对应资源关联。上传其他组的数据不会清理已有附件。当前没有自动学年结转、资源回收站或目录批量导入。

## 部署说明

密码使用加盐 scrypt 派生值保存；会话保存在 SQLite，浏览器使用 HttpOnly、SameSite=Strict Cookie。外网部署使用 HTTPS 反向代理，并配置 `COOKIE_SECURE=true`。账号版启动需要连接服务端完成身份验证；便携版不提供多人权限。

本地验收环境可在 `127.0.0.1:8081` 独立运行，数据存放在 `data/multiuser-preview`，与原工作空间分开。这里的演示账号仅供本地测试，不能用于生产部署。

密码派生与会话设计参考 [Node.js scrypt 文档](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback) 和 [OWASP 会话管理指南](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。
